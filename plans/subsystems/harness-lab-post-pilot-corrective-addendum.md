## 1. Purpose and ownership boundary

Qualify the **developer-only**, Python-driven, private-daemon CodeGG Harness Lab as a trustworthy instrument for improving the agent-facing harness, not CodeGG product features or general model performance. Close observed defects in failure/usage evidence and optimize/evaluator correctness, then prove an actual bounded OpenCode proposal/build/retest attempt, followed by sustained real-agent workload evaluation.

Python remains the stable, independent experiment controller and scoring authority. OpenCode is optional and is only the **source-code proposer**; CodeGG ACP talks to the real native daemon/scheduler/broker. A subject candidate cannot modify its independent verifier/hidden holdout, experiment budget, ledger or controller. Changes to those contracts require a separately reviewed controller version, not candidate promotion.

The approved environment is the user's **trusted separate development workstation**: **no VM/container provision, no local-isolation research milestone, no request for interactive permissions during authorized benchmark turns**. Explicit `yolo + full-host` exercises true tool freedom, or `yolo + workspace-write` is a separately qualified more restricted profile; explicit Deny still wins. The multiple per-root daemon lanes, unique databases, worktrees, owned-process cleanup and production-default-daemon protections implemented by M001/M002 remain mandatory.

## 2. Corrective findings, underlying evidence, and why prior verification missed them

1. **F001 — Native failed-turn diagnostics/usage gap (M005).** Live Muse Spark 1.3's Task 1 emitted 7 completed tool calls, then `HarnessTurnFailure`, no changed task file, no useful provider terminal usage and no detailed error classification. Its 10 verifier tests failed, and Task 2 was stopped under the spending rule. In `src/acp.rs`, successful `TurnCompleted` returns optional `codeggUsage`; `TurnFailed` currently becomes generic ACP JSON-RPC error `-32010` with session/turn IDs only. Existing happy-path tool fixtures did not exercise real failed-provider turns with usage/disclosure.
2. **F002 — Missing enforceable spend semantics (M005).** Token counts/cost may be unavailable, especially on failures and subscription/provider adapters; an absence is never zero. The recorded pilot explicitly stopped because configured usage limits could not be independently enforced. A fixed provider account subscription is not by itself a measurable per-experiment financial hard limit. Preflight tests and happy-path usage did not prove failure-path coverage or remote/third-party quota enforcement.
3. **F003 — Acceptance criterion overly narrow / negative-controls confusion (M004).** `qualify_candidate` checks candidate expected-terminal matches, paired nonregression and an improvement where a baseline terminal differs from an expected terminal; the frozen 12-case suite already matches all expected terminals (including **intentional negatives**), so no real candidate can be accepted on that evidence. `ledger.compare` summarizes terminal labels and omits performance distributions/denominator provenance needed for efficiency-only acceptance. Correctness gates prevented false acceptance but did not prove genuine optimization.
4. **F004 — Interrupted qualification evidence gap (M004/M005).** The old M004 closure recorded fail-closed on partial candidate rows; M005 later added immutable-prefix candidate resume. It has focused tests, but there is no independent **live subprocess interruption during candidate scoring -> restart -> complete without duplicate receipts** qualification. Status must be reconciled with the new code rather than reimplementing a closed unit-test feature.
5. **F005 — OpenCode real proposer/correction/accepted fix unproven (M004).** An OpenCode 1.19.0 adapter, fake responses, scoped worktrees, required changelog, compile retry and candidate gates exist. No authenticated real OpenCode patch, compile correction and independently accepted defect fix was run. Deterministic mock tests are not interchangeable with live provider evidence. **Discharged:** an authenticated OpenCode 1.19.3 proposal was accepted, and a live compile-correction trace (a real compiler diagnostic handed to the proposer, its correction re-gated and accepted) is preserved at `plans/closure/harness-lab/evidence/compile-correction-20261022.json`.
6. **F006 — Sustained/multitask agent experience unproven (M005).** First paired task: LongCat passed 10/10 tests with usage; Muse Spark failed without terminal usage; second frozen task not run. Existing 12-case fixtures are provider-free scripted tool chains; they do not establish half-hour-plus agent continuity, real task correctness across agents/models, recovery from provider/transport faults, background jobs, subagents/worktrees, or MCP/LSP coverage. Expand only after spending and evaluator invariants are proven.
7. **F007 — The taxonomy's protected stall-stop control was never exercised (C005).** The `repeated-identical-failure-stall` control asks the agent to read a file that does not exist. In every live trial the agent read it, the read failed, and the agent then **investigated differently** — it listed the directory and read another file — and correctly reported that the file does not exist. The identical failing call was never repeated, so the stall-stop branch was never entered, the verifier refused to confirm the trial, and `control.no_regression` measured 0.0 on both sides of the comparison. The control reported the truth faithfully; it simply never got the situation it is about. Prior verification missed it because the control's *expected* outcome is "not solved", which a vacuous run also satisfies: the case could not fail, so nothing tested whether it could ever fire. **The induced variant does not change the agent's behaviour.** C005's live exercise ran five trials of a new induced case whose fault makes the read fail deterministically (`unreadable`), and in all five the fault fired and the agent **still** investigated differently and ended the turn `completed` — the longest identical-failure run was 1 in every trial, so the control was never exercised. C005 therefore closes on the plan's own pre-stated fallback, with the control's expectations unedited and the case still in the suite.
8. **F008 — Live-trial integrity and the cumulative resume deadline (C006).** Two distinct measurement defects. **First**, the daemon's socket event forwarder handles a bounded-broadcast lag by logging a warning and **continuing** (`src/core/transport/daemon_socket.rs:1255-1257`): the dropped events never reach the consumer, and `src/acp.rs` has no `Lagged` handling at all, so an ACP consumer can be left with a `tool_call` whose `tool_call_update` was dropped. **Second**, the cumulative wallclock deadline exists in exactly one command: `optimize` persists an absolute `deadline_unix` in its immutable inputs and restores it on a resume, but `qualify` and `evaluate` — the two that actually perform a qualification — enforce `--max-wallclock` against a process-local `started` that is re-created on every invocation (`dev/harness_lab/improve.py:1060`, `dev/harness_lab/__main__.py:551,576`). A resumed qualification therefore restarts its wallclock budget at full length, and the total a single candidate qualification may consume is unbounded in the number of resumes. Prior verification missed both because the harness's verification is offline and deterministic, and because every interruption proof kills the process **between** trials, at a point where the remaining budget was still ample: a budget that is only ever resumed with budget to spare cannot fail to be cumulative. **The live measurement ran and the rate is still not established.** Fourteen live trials of the full supported taxonomy (on the operator-approved route under the operator-approved budget policy) observed **no** event-stream gap and **no** unmeasured terminal: 14 of 14 ended in a terminal that carried an observation. Zero observed in fourteen is a **count**, not a rate — the 95% upper bound on the true rate is about 19% — so the rate is recorded as *not established*, never as zero, and the denominator it would have needed is named: a run in which a loss is observed. The sustained scenario ran too (three trials, 121,097 ms against a 1,500,000 ms cumulative cap, none stopped, none unattempted), but it **cannot** contribute a denominator for event loss: the `codegg_event_gap` observation is read only by the autonomy runner.
9. **F009 — A dead public config key, and the guard hole that hid it (C007). — CLOSED.** `ProviderConfig.chunk_timeout` **was** declared in the configuration schema, documented in `architecture/config.md`, merged across layers, and read by **no** provider: the `wire.rs` plumbing that could have carried it was fed from two hard-coded 30 s call sites (`opencode_zen`, `openai_compatible`) and from `None` everywhere else, and **nothing** ever fed it the configured value. It was never live. The static guard that exists to prevent exactly this class of defect — `scripts/check_config_merge_coverage.py` — covers only the **top-level** `Config` struct and does not descend into the nested configuration structs that own their own `merge` method, `ProviderConfig` among them (there are **seventeen** such owners, all of them reachable from `Config`). A nested field with no merge arm parses without error and is silently discarded for every config layer, which is the failure the guard's own docstring describes, unguarded. Prior verification missed it because the guard passes as long as the nested struct appears as one covered field on `Config`. **Discharged by C007:** the key and its merge arm are gone; the provider-side plumbing that could have carried it is gone with them, so no provider imposes a per-chunk deadline; an existing config file that still carries the key keeps parsing and produces the same effective configuration (proven by execution, not asserted); and the guard now derives the reachable nested structs from source and requires merge coverage of every one that owns its own `merge`. Closure: `plans/closure/harness-lab-post-pilot-corrective/007-status.md`.
10. **F010 — The approved free routes are unmapped in the shared provider profile (owned outside this repository).** The operator's approved route set includes `beam-free` and `minimax-m3.1-flash-free`. Both are served by the provider and both are placed by the current first-party OpenCode Go endpoint table, but neither has a wire-map hint in the shared provider profile, so the CodeGG subject fails them closed at `wire_unresolved`. `longcat-2.5-preview-free` has a hint and is withdrawn from the provider's catalog, and its upstream answers HTTP 402 — a hint for an unavailable model is harmless, whereas a missing hint for an available one is what breaks a consumer. The shared profile is owned outside this repository, so this condition is **not** a CodeGG defect and gets **no** CodeGG-side plan: it is owned by EggPool's Shared Provider Profile Contract M002 (`../gorouter`, `plans/implementation/shared-provider-profile-contract/002-opencode-go-current-endpoint-wire-hints.md`), which re-reviews the first-party table, adds the missing non-fixed hints, and adds a guard comparing the reviewed record, the wire map and the live catalog. M002 cannot restore `longcat-2.5-preview-free`; only the upstream can.
11. **F011 — The goal checkpoint journal append was never flushed (inherited defect, found while obtaining exact-head CI). — CLOSED.** `append_checkpoint_update()` wrote the update block through `tokio::fs::File` and dropped the handle without an explicit flush. `tokio::fs::File` buffers writes and hands them to the operating system on **flush**, not on **write**, so the appended bytes could still be in flight when the call returned: the next reader of the journal observed a truncated journal and silently lost the newest update. That reader is not a test — it is the model-facing `goal_update_progress` path, the daemon goal path, and the turn-start tail read, all of which read the journal back immediately after appending to it. The sibling index append in `run_store.rs` already flushes for exactly this reason. Prior verification missed it because the defect is invisible to a test that reads the journal only after the runtime has had a chance to run the pending drop-time flush: `goal::checkpoint::tests::test_read_checkpoint_tail_returns_latest_updates` failed on a hosted Linux run of this branch, and on two hosted runs of an **unrelated** branch, while `crates/codegg-core/src/goal/checkpoint.rs` is byte-identical to `origin/main` — an inherited defect, not branch evidence. **Discharged:** the append flushes before it returns, a regression test reads the file back synchronously and immediately to prove the bytes are there (it fails deterministically without the flush), and `architecture/goal.md` records the contract.

## 6. Cross-cutting requirements

### Storage and migrations
No production DB schema migration by default. The external ledger/assessment/score/checkpoint schema must be versioned and must migrate or reject pre-corrective records explicitly; the original 2026-10-21 pilot JSON is **immutable**. Redact credentials/provider response bodies, prohibit hidden reasoning in public ACP/ledger.

### Protocol
ACP v1 remains a thin native adapter. Add optional namespaced terminal error `data` / observability only when canonical daemon data already exists or a bounded authorized native DTO is justified. Never forge token usage or standard ACP stop reasons; no global policy bypass.

### Concurrency, recovery and security
Support >1 concurrently bound private daemon. Candidate binary/daemon generation/candidate patch/test suite/score contract must match their frozen receipts. Restart never overwrites a prior terminal row; ambiguous in-flight attempts are explicit and reconciled, not silently replayed. Full-host is trusted-user authority; workspace-write is not equivalent. The Python supervisor owns process groups and rollback, OpenCode cannot self-accept.

### Metrics and budgets
Observed usage, unavailable usage, and upper-bound reserved budget are distinct. Provider-side caps are only claimed if verifiably enforced for the selected route/failure path. No locally estimated tokens or prices may be labeled actual or treated as enforceable spend ceilings. If a hard dollar cap is requested and only post-hoc usage exists, decline launch absent a proper source of authority.

### Portability and external dependencies
Developer Python is optional. OpenCode is pinned/qualified and optional; `ManualProposer` works offline. Ordinary CI MUST be credential-free, deterministic, and bounded; live model runs are manual and separately labeled.

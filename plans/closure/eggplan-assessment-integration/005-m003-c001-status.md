## 3. Production implementation evidence

- `crates/codegg-core/src/jobs/mod.rs`: `ExecutionSubjectRevision` gains
  `eggplan_dirty_digest: Option<String>` (`#[serde(default,
  skip_serializing_if)]`, `deny_unknown_fields` retained);
  `SCHEMA_VERSION=2`, `SCHEMA_VERSION_V1=1`;
  `is_valid_eggplan_dirty_digest` (`sha256:<64-lowercase-hex>`); `validate()`
  accepts v1+v2 explicitly (v1 must not carry the new field; clean requires
  both digests absent; dirty requires native, optional Eggplan in form).
  `ExecutionSubjectProvenance::SCHEMA_VERSION` unchanged (1); derived
  equality carries the v2 field through Stable/Drifted decisions with no
  store-code change. `to_eggplan_fields` (M002) untouched. No Eggplan crate
  dependency in `codegg-core` (guard 6c).
- `src/execution_subject_capture.rs` (new, application layer): single
  `capture_attempt_revision(workspace_root, workspace_id)` helper. Native
  error→reason mapping is byte-identical to the pre-C001 scheduler mapping
  (`NotGit`/`UnsafePath`/`BoundsExceeded`/`CaptureFailed`). The Eggplan side
  is best-effort: skip without store I/O when `.eggplan/` is absent; else
  `open_read_only` validation followed by
  `eggplan_repo::capture_git_subject_fingerprint` (pin `0dd33b7`) for the
  workspace with `.eggplan` excluded, attach only on equal
  revision + equal clean/dirty state + valid digest form. No paths/content
  persisted; no post-attempt backfill API exists (guard 6b).
- `src/scheduler/scheduler.rs`: attempt-start and Local seal paths call the
  helper; struct literals removed. `src/scheduler/executor.rs`:
  materialized seal calls the helper.
- `src/work_plan_repository_binding.rs`: `prove_identity` performs the
  E1/C/E2 sandwich and delegates to private pure
  `prove_identity_from_captures` (E1==E2 exact else
  `repository_subject_changed_during_identity_proof`; then revision/state
  checks else `repository_subject_mismatch`; dirty binding carries E1/E2's
  Eggplan digest as the proven Eggplan-side digest, native digest as
  diagnostics). `translate_historical_subject` validates, translates clean
  as before, translates dirty only via `eggplan_dirty_digest` (normalized),
  and fails closed with `legacy_dirty_subject_missing_eggplan_digest`.
- `src/work_plan_eggplan.rs`: `capture_current_subject` unchanged apart from
  the new `None` field (M002 transient semantics preserved).
- No DB migration: the physical `source_subject_json` column already stores
  versioned JSON; `STORAGE_LAYOUT_VERSION` stays 68.

## Objective, bounded hypothesis and evidence

C035's child reached user code, wrote stage proof, was attested as low-integrity and returned `ERROR_ACCESS_DENIED` opening the synthetic host path. The harness set `capture.output_path = Some(.../denials.json)` under an existing directory, but then used `fs::read(&capture_path)`. Current MXC documentation says capture output filenames are stamped with a run ID (e.g. `denials.<run-id>.json`) and the authoritative absolute path and summary come from output metadata after a terminal wait. **First confirm the exact semantics in the repo's pinned `mxc-sdk = "=1.0.0"` source and returned `v1::run` type.** If present, the observed "capture missing" likely reflects a caller filename assumption rather than failing capture. No unconditional conclusion until the exact build is inspected and tested.

The sole objective is accurate, per-execution, enforcing-mode audit provenance for a real synthetic denied-read child, with a negative/no-event control and false-positive prevention. Do not expand scope to Win32 handle inheritance (C037), alter runtime sandbox configuration, or claim production admission.

No raw user paths/credentials in CI summary; synthetic fixtures only.

## Work packages with decision gates

**A — SDK output contract provenance.** Identify the exact pinned crate source/tag in Cargo.lock, read the v1.0.0 `v1::run` output/result metadata types (including whether `output_metadata` or capture pointer exists), and establish whether the caller-supplied `denials.json` is transformed into a stamped filename. Build a tiny deterministic test against the pinned version, not docs on `main` alone. Record exact crate checksum/source, OS edition/build/UBR and runtime feature probe. If the pinned API lacks output metadata, first inspect its stdout/stderr/pointer contract, then use a constrained run-unique directory enumeration with strict prefix and JSON validation as a **diagnostic fallback**, not a reusable global "first JSON" heuristic. A version bump is *not* authorized by this plan absent an explicit side-by-side diagnostic necessity with preserved old pin.

**B — Correct metadata discovery and validation.** Use actual returned authoritative output path if available; validate it resides inside the owned capture root (or record and explicitly handle a documented managed-temp output), has the correct stamped filename, was created **after** this invocation start, is a regular file with no reparse/symlink redirect, size is bounded, is valid JSON with `denials[]` and `summary{exitCode,totalDenials,deniedResourcesTruncated}`. Correlate event time/process ID to the child and allowed descendants; reject stale, duplicate, wrong nonce, unexpected directory, mismatched exit, truncated capture (for strict completeness claims), mode mismatch or missing/unknown metadata. A denial count alone is insufficient without matching a real child access. Never consume C033's capture result as evidence for C036.

**C — Minimal live matrix.** On the same eligible Windows 11 host execute (1) an ordinary, uncontained **positive** read of the broadly readable synthetic file, (2) a real enforcing MXC child that reaches entry and gets `ERROR_ACCESS_DENIED` on the *same file*, and (3) an allowed stage-only read/write with no disallowed operation. Run each in separate output capture directories, with distinct nonce and timed child entry. Assert block-mode path-denial result is reflected by a correlated capture event when the pinned backend claims capture support; allowed-only case must not fabricate the denied file event. Include capture disabled/no-operation negative controls to verify the parser cannot "find" stale denials. Identify ETW/no-data/metadata-generation errors explicitly; no permission relaxation to make events appear.

**D — Failure lifecycle and evidence.** Exercise a pre-entry helper failure, bounded timeout and a missing/stale/foreign JSON document. They must classify respectively `not_run/failed/unavailable`, not denied. Require actual exit/terminal wait before evaluating metadata, verify cleanup of capture temporary files and any retained ETL (if diagnostic retention explicitly enabled; disabled by default). If capture is structurally unavailable in pinned v1.0.0 despite selected capabilities, stop at a documented limitation. Record a machine-readable `C036_REPORT` with `capture_contract_kind, actual_output_path_redacted, output_metadata_present, filename_stamped, document_verified, matched_denial_count, event_pid_correlated, capture_mode, host_read_result, child_entry, child_exit, observed_tier, qualified_test_only` and failed gates; attach raw synthetic JSON artifact with short TTL if appropriate.

## Acceptance, negative/blocked boundaries and closure

Strict-positive **test-only C036** only if exact pinned SDK provenance is recorded; no-container positive read; actual MXC child reaches user code and gets `ERROR_ACCESS_DENIED`; block-mode capture is independently attributable to that child/request using validated output location and event(s) with no truncation; negative/no-event/stale/missing controls are not false positives; stage permission and original descriptor/content/IDs unchanged; no leftover processes or ETL. If the SDK records zero despite a real denied operation and truthful supported capability probe, close negative with error details; if host/version unavailable, close blocked.

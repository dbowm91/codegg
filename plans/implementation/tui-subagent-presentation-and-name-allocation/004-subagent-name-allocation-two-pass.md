# TUI Subagent Presentation and Name Allocation — Milestone P004 — A Free Pool Name Beats a Numeric Variant

Status: closed — closure `plans/closure/tui-subagent-presentation-and-name-allocation/004-status.md`

Outcome: a newly spawned subagent now receives a **bare pool name** whenever
any pool name is free. The draw is two passes over the same pool in the same
random order: the first pass returns the first base name that is **not held**,
and only when every base name is held does the second pass walk the `-N`
suffix ladder. The suffix is now the fallback it was always meant to be,
instead of the primary mechanism — under the old rule the first occupied base
the walk reached consumed `-2` while forty-five other names sat free.

The plan's §10.3 test could only be written probabilistically ("this cannot be
pinned without seeding the RNG"). The draw was therefore split into `draw` and
`draw_from(active, start)`, so the selection rule can be exercised at **every**
start index: the rule is now pinned deterministically rather than by a
probability, and the non-vacuity proof is a deterministic failure rather than a
likely one. The split is behaviour-neutral — `draw` computes the random start
exactly as before and hands it to `draw_from`.

Nothing else moved. The lease, the release, the event, the draw site, and
`pool_entry`'s suffix stripping are untouched, so replay determinism and
attribution are unchanged; a `Sally-2` recorded before this change stays
`Sally-2`, and it still resolves to the Sally entry and keeps its persona.
The policy is stated identically in the registry's module doc, the generator's
emitted text, the pool source's header, and `architecture/tui.md`, and the
generated file was regenerated by its generator — its diff is a doc comment
and nothing else.

## 1. Objective

A newly spawned subagent receives a **different pool name** whenever any pool name is free.

Today the numeric suffix is the *primary* mechanism rather than the fallback: the first occupied base name the draw lands on takes `-2` even though roughly forty-five other names are free.

## 2. Why this milestone is ready

- **Hard dependencies:** none. P004 touches `src/agent/subagent_names/registry.rs`, the name-pool generator and its source, and two documentation files. It does not touch `src/tui/` at all and is independent of P001–P003.
- **Interface dependency:** none.
- No protocol, projection, storage, or execution change: the registry is an in-memory active-lease table and the name still travels inside the spawn event.

### 3.1 The draw

`SubagentNameRegistry::draw` (`src/agent/subagent_names/registry.rs:149-176`):

```rust
let start = random_index(SUBAGENT_NAMES.len());
for step in 0..SUBAGENT_NAMES.len() {
    let idx = (start + step) % SUBAGENT_NAMES.len();
    let base = &SUBAGENT_NAMES[idx].name;
    let candidate = first_free(base, active);
    if let Some(name) = candidate {
        return name;
    }
}
format!("{FALLBACK}-{}", active.len() + 1)
```

and `first_free` (`registry.rs:182-193`):

```rust
fn first_free(base: &str, active: &HashMap<u64, String>) -> Option<String> {
    if !is_taken(base, active) {
        return Some(base.to_string());
    }
    for suffix in 2..=MAX_SUFFIX {
        let candidate = format!("{base}-{suffix}");
        if !is_taken(&candidate, active) {
            return Some(candidate);
        }
    }
    None
}
```

The walk calls `first_free` on the **first** base it reaches. If that base is held, `first_free` returns `base-2` — and the draw returns immediately. The other ~45 pool names are never consulted.

### 3.2 The pool is large relative to the number of live subagents

- The pool holds **46** entries (`assets/subagent-names/names.toml` → `src/agent/subagent_names/generated.rs`).
- The projection caps the agent tree at `MAX_PROJECTION_SUBAGENTS = 16` (`crates/codegg-protocol/src/projection/limits.rs:67`).

So a free bare name essentially always exists, and the suffix is reached only when every one of the 46 bases is held — a state the projection's own cap makes rare.

### 3.3 The state the change can rely on

- **The registry is active-scoped.** `SubagentNameLease`'s `Drop` releases the name (`registry.rs:268-272`), so "already used by an active agent" is exactly the existing lease notion. **No new state is needed.**
- **The suffix does not orphan a descriptor.** `pool_entry` (`registry.rs:279-290`) strips a numeric suffix, so `Sally-2` still resolves to the Sally entry and keeps its persona. The change makes suffixed names rarer; it cannot break attribution.
- **Replay determinism is unaffected.** The name is drawn **once at spawn** and travels inside the event (`registry.rs:9-19`; the module doc explains why: a reducer that re-drew on replay would produce a different name for the same event stream, and a durable `agent_run` row would disagree with the live view). The policy change therefore affects **new spawns only**. Sessions recorded before the change keep their `Sally-2` names, and that is correct.
- **The draw is the only place a name is minted.** `src/agent/worker.rs` is the only publisher of `AppEvent::SubagentStarted` and it draws the name; the reducer and the TUI never draw one.

## 4. Invariants that must not regress

- **I7 — The name is drawn once, at spawn.** The draw site stays where it is (`src/agent/subagent_names/registry.rs`, called from `src/agent/worker.rs`). The reducer and the TUI must never draw a name.
- **Replay determinism.** A replayed event stream must reproduce the recorded names. The change must not make the draw depend on anything outside the active set at spawn time.
- **The lease is still released on every terminal path** — completion, failure, cancellation, panic — by construction through `Drop` (`registry.rs:268-272`).
- **No name is ever handed out twice while held.** `is_taken` (`registry.rs:195-197`) stays the single collision check.
- **The empty-pool and exhausted-pool fallbacks still hold** (`registry.rs:159-162` and `:173-175`).
- **`pool_entry` still resolves a suffixed name to its pool entry.**

## 6. Required production changes

### Runtime and concurrency

1. **Two-pass draw.** `draw` becomes:

   - **Pass 1 — a free base name.** Walk the pool in the same random order the current code uses, and return the first base name that is **not held**, verbatim and without a suffix.
   - **Pass 2 — the numeric fallback.** Only if pass 1 found nothing (every base is held), walk the pool again in the same random order and return the first `first_free(base, …)` result — the existing suffix ladder.
   - **Last resort.** If pass 2 also finds nothing (every base and every suffix up to `MAX_SUFFIX` is held), keep today's `format!("{FALLBACK}-{}", active.len() + 1)` fallback.

   The random start index is computed **once** and both passes use it, so the two passes agree on the ordering and the result is still spread across the pool rather than always starting at index 0.

   `first_free` and `is_taken` are **retained** — pass 2 uses them, and they are what the existing tests exercise directly.

   The cost is at most 46 additional `is_taken` calls, each O(active). With `MAX_PROJECTION_SUBAGENTS = 16` that is negligible, and the draw happens once per spawn.

2. **No change to the lease, the release, or the event.** The name still travels inside `AppEvent::SubagentStarted` exactly as it does now.

### Documentation and static guards

3. **Update the module doc** (`registry.rs:21-27`) to state the new policy: a free pool name is preferred; the numeric variant is the fallback when every pool name is held.

4. **Update the generator's emitted doc text** (`scripts/generate_subagent_names.py:123-126`) and **regenerate** `src/agent/subagent_names/generated.rs` with `python3 scripts/generate_subagent_names.py`.

5. **Update the TOML source's header comment** (`assets/subagent-names/names.toml:10`) to match. The TOML file is the generator's input, so this and step 4 must agree.

6. **Update `architecture/tui.md:752-754`** so the architecture doc states the same policy the code implements.

7. **No new static guard.** The behaviour is fully covered by unit tests. `scripts/generate_subagent_names.py --check` must pass, proving the generated file is in sync with its source.

## 8. Failure, cancellation, restart, and contention semantics

- No new state, no new locks, no new async. The registry's mutex is held exactly as long as it is today.
- The draw remains **deterministic given the active set and the random start**; the only change is which name is preferred.
- A spawn that fails after the draw still releases the name through `Drop` — unchanged.
- On restart there is nothing to restore: the registry is empty and the pool is fully free. Unchanged.

## 9. Compatibility and migration

- **No migration.** Names are not durable state.
- **Backward compatibility:** an event recorded before this change carries its recorded name, and replay reproduces it. A `Sally-2` in an old session stays `Sally-2`; `pool_entry` resolves it exactly as before.
- **Forward compatibility:** a name drawn under the new policy is an ordinary pool name with no suffix; nothing downstream distinguishes it.

## 10. Required tests

### Focused unit tests

1. **A free base name is preferred over a suffix.** Occupy **every base name except one**; assert the draw returns exactly that one, with **no** `-N` suffix. This test is deterministic regardless of the random start index, because only one bare name is free.

2. **The suffix is used only when the pool is exhausted.** Occupy every base name; assert the result carries a `-N` suffix (this is the existing `draw_survives_a_pool_where_the_chosen_base_is_occupied` at `registry.rs:433`, whose intent the change preserves).

3. **The occupied-first-base case.** Occupy the base that the *random* walk is most likely to reach first — this cannot be pinned without seeding the RNG, so instead occupy a **randomly chosen** subset of bases large enough that the naive implementation would fail often, and assert over many draws that **no** draw returns a suffixed name while a bare name is free. Run enough draws (e.g. 200) that the old implementation would fail the assertion with near-certainty — the test must be **non-vacuous**, i.e. it fails against the pre-change implementation.

4. **A suffixed name still resolves to its pool entry.** `pool_entry("Sally-2")` still returns the Sally entry (existing test at `registry.rs:568`; retained).

5. **No name is handed out twice.** With the pool fully occupied, the drawn name is not in the active set (existing assertions in `draw_survives_a_pool_where_the_chosen_base_is_occupied`).

### Integration tests

None required — the registry is not on a wire path and the projection copies the name verbatim.

### Restart and recovery tests

None. The registry holds nothing across a restart.

### Contention and cancellation tests

- The existing `lease_names_are_distinct_across_concurrent_holders` test (`registry.rs:553`) must remain green: concurrent leases must still receive distinct names. Under the new policy this is **more** strongly true (distinct bare names, not distinct variants of one base).

### Security and negative tests

None specific. No untrusted input reaches this code.

## 13. Acceptance criteria

1. With at least one free pool name, a newly spawned subagent receives a **bare** pool name — never a `-N` variant.
2. With every pool name held, the numeric ladder still applies and the drawn name does not collide.
3. With every pool name and every suffix held, the `Agent-N` fallback still applies.
4. The name is still drawn **once at spawn**, travels inside the event, and replays identically.
5. `pool_entry` still resolves a suffixed name to its pool entry.
6. The four policy statements (§3.5) describe the same policy, and `python3 scripts/generate_subagent_names.py --check` exits 0.
7. `git diff src/agent/subagent_names/generated.rs` shows **only** a doc-comment change.

## 14. Stop conditions

Stop and report rather than improvise when:

- The change would require the name to be drawn anywhere other than the spawn site — that would break replay determinism (I7).
- The change would require a durable name record, a migration, or a protocol field.
- The pool's *contents* appear to need to change. They do not; only the order they are tried in changes.
- The new tests cannot be shown to fail against the pre-change implementation. An assertion that passes both before and after proves nothing.

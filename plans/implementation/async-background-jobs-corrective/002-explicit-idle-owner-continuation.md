# Async Background Jobs Corrective C002 — Explicitly Authorized Idle Owner Continuation

Status: ready for handoff
Baseline: `21b35c79abca665f353b1a744073c6a17f7a9c6e` (C001 closed; revalidate latest corrective head before editing).
Roadmap: `plans/subsystems/async-background-jobs-idle-completion-corrective-addendum.md`
Predecessor milestone/closure: M003 `plans/closure/async-background-jobs/003-status.md`; consumes M001/2/4 and C001 daemon completion publisher.
Class: capability + security invariant. Hard dependency C001; interface dependency canonical `CoreDaemon` turn runtime/session request and principal authorization contract.

## 1. Objective and concrete defect

When an authorized user/task explicitly requests "run the build/watch CI and continue once it finishes," provide a real **idle-to-active agent transition** on the durable terminal event, even when `AgentLoop::run()` has ended and no TUI/client reconnects. This requires a single new, bounded **normal** owner turn, not a resume marker that waits for the next unrelated user message. Keep `notify_only` as the default with zero autonomous model tokens.

Today `src/agent/job_notification_recovery.rs::settle_lease_for_delivered` CAS-consumes the M003 single-use `JobContinuationLease` and attaches "[resume authorized...]" text during next-turn notification injection. `src/agent/follow_up.rs` explicitly uses nonblocking `try_recv`, which does not keep an idle agent alive. `src/agent/loop.rs::run_inner` only injects pending notices when invoked; `src/agent/turn_runtime.rs` runs model work inside a task created per request. Thus existing `resume_owner` is a **next-turn hint**, despite language implying an actual continuation. C001 will provide a daemon-owned terminal publisher even while no model is active.

## 2. Security and authority design gate

Before implementing, document one explicit product contract for consent:

- `on_complete=notify_only` remains the immutable default and **must never enqueue a model invocation**. The model can request a watch but cannot silently authorize extra inference/tool actions for a user merely by setting `on_complete=resume_owner`. An additional host-trusted, user/task-approved continuation grant is required; without it `resume_owner` becomes notify-only or is rejected **before** the operation is accepted. Existing legacy lease rows without verifiable grant must not auto-resume after upgrade.
- Bind a durable grant to authenticated principal, session, project/workspace, originating task/turn, accepted `JobId`/`ciwatch` notice identity, allowed model/provider connection and permission/sandbox ceilings, expiry, maximum continuations (default **1**), inference token/time/tool-call budget, and user cancellation semantics. Where current domain model cannot prove principal/session ownership, fail closed and send attention.
- A completion event is **untrusted data** until matched to final `JobStore` state or validated C001 GitHub-watch state. Only host-authored compact status/result refs enter system/instruction context; remote CI titles, logs and action names stay untrusted inert data. Do not allow a watcher to craft user-role messages or bypass tool permissions.
- The canonical daemon session/turn concurrency policy decides whether the owner is idle. If another turn is already running, queue a bounded single follow-up at a safe boundary or park for attention according to user policy; **never** start a second simultaneous owner provider loop or inject into a different turn. Preserve active steer/cancel/approval handling. Detached job completion must not reactivate archived/deleted/inaccessible sessions.
- Independent from dispatcher restart, at most one admitted continuation turn per notice/grant; no duplicate inference after failure before durable dispatch record. A crash after provider submission but before response is **ambiguous** and must transition to `needs_attention` instead of automatic replay. Exactly-once logical admission is possible; exactly-once external provider execution is not guaranteed, so do not advertise it.
- Resume must route via the same authenticated `CoreRequest`/turn-runtime/`JobSubmissionService` path as ordinary host-authorized turns. A scheduler/CI callback never invokes `AgentLoop.run()` directly, never substitutes principal authentication, and never creates an unbounded recursion/workflow engine.
- Completion priority/resource budgets are fair across projects/sessions; cap queued continuations per daemon/session and time-to-live, and rate-limit provider retries. SBC-first idle overhead should be negligible. User cancel, stale session, revocation, expiry and quota exhaustion always win before provider invocation.

If current product authority cannot represent user consent across unattended execution, choose the **safe partial closure**: retain notify-only and create a documented blocked decision seam rather than implementing a model-supplied autonomy flag. Do not weaken the boundary to meet the acceptance matrix.

## 3. Ordered work packages

A. **Contract and threat model.** Determine existing parent-session `CoreRequest` dispatch path, turn admission identity, session authorization, user-approved task/work-order capabilities, and provider/cancel wiring (inspect `src/core/daemon.rs`, `src/core/session_runtime.rs`, `src/agent/turn_runtime.rs`, `src/agent/run_control.rs`, `src/scheduler/job_notifications.rs`, `crates/codegg-core/src/session/schema.rs`, session/client DTO, `architecture/authorization.md`). Freeze explicit grant API and deny matrices before enabling idle inference. A model-facing field alone is never sufficient.

B. **Durable attention versus resume state.** Refactor C001 completion handling into one persisted, stable notice event for `notify_only`, and a separate typed `ContinuationIntent`/grant claim for `resume_owner`. Session visibility must never rely on a system message only at a future agent turn. Preserve M001/M017 semantic session-event identity and original `JobContinuationLease` data; additive migration if needed, with old unverified leases non-autonomous. Use `Pending -> Eligible -> Claimed -> TurnAccepted -> Started -> Completed` plus `Suppressed/Expired/NeedsAttention` (names flexible) with DB CAS and unique `notice_id + grant_id`. Prove first-write/claimed-at-most-once at two daemon instances/frontends.

C. **Canonical turn request and credential context.** The daemon-owned completion coordinator retrieves the current approved request/session/model policy using authenticated persisted context, verifies grant and concurrency/steer/cancel/budget gates, and submits exactly one new **standard** turn request. Persist accepted turn ID and cause `completed_background_job` before model dispatch; use existing job/turn scheduler for admission. Preserve user consent and tool-policy snapshot/permission decisions; do not serialize short-lived live provider credentials. Attach the verified terminal summary and artifact reference to authorized prompt context without forging a new user utterance.

D. **Live safe-boundary versus fully idle.** If owner turn remains live, deliver a bounded follow-up through the exact `(session_id,turn_id)` routing without concurrently invoking the provider. If turn already ended, dispatch a newly authorized continuation exactly once; notifications still publish with no model. Handle completion racing with `TurnFinished`/unregister, two TUI clients and repeated `run_control` sends. Never let a full/closed channel swallow the durable resume intent.

E. **Cancellation and negative cases.** User explicitly stops the session or revokes the grant before model start; subscriber role changes, workspace removed, provider unavailable, budget expired, server restarts, unsafe command pending approval, terminal CI needs-attention/neutral/skipped or cancelled job. All decline autonomous resume and keep one actionable notice. Resuming a failed build may be explicitly authorized only if policy says so; do not interpret error/status text as permission for autonomous fixes.

F. **UX/docs and handoff.** Surface clear `on_complete` semantics: default notify only; `resume_owner` *requires* an explicit authorization grant and may autonomously spend bounded tokens once. Show grant/queued/resumed/declined/expired status, and a user-visible cancel control through existing session/attention projections (no TUI polling). Update `architecture/agent.md`, `architecture/jobs.md`, `architecture/authorization.md`, `architecture/projection.md`, tool descriptions and configuration. Preserve original M003 closure as history.

## 4. Required deterministic acceptance

1. **No-actor, opt-in:** Real daemon + SQLite + fake provider. Authorized user creates a background `bash` test or `ci_watch` with **explicit external grant**; originating turn ends. Terminal event arrives while daemon idle and **without any further user request or tool call** queues exactly one canonical owner turn. Fake provider observes one invocation, correct owner/session/model/tool permission ceilings and verified notice, within bound.
2. **Default:** Identical sequence without a grant or with `notify_only` persists visible notice, **zero** provider calls, zero new turns and no synthesized user prompt. A model setting `resume_owner` without grant gets explicit denial/notify-only; no bypass.
3. **CAS/crash matrix:** crash after notice commit; after resume claim; after turn record accepted; before/after provider entry. An exact-grant/notice replay never queues two turns. Ambiguous provider-side start records `needs_attention` rather than replay. Test concurrent 50 resume contenders and two frontends.
4. **Security/concurrency:** session archiving, user cancel, revocation, grant expiry, exhausted token/tool budget, changed principal, new concurrent turn, wrong workspace, wrong watch/repo, malicious GitHub payload and disabled provider all fail closed. An observer cannot authorize or view private result. Existing sandbox/approval ceilings still apply.
5. **Compatibility:** foreground behavior, M001/M002/M003/M004 notices, M017 Tool Programs, AgentRun M009, headless and remote frontend safe-dispatch unchanged. No hidden second scheduler/agent runner, no high-rate wake/poll loop.

Focused new integration test `tests/job_continuation_c002_idle_resume.rs` (or equivalent), M003 `tests/job_continuation_m003_visibility.rs`, `tests/job_notification_m001_contract.rs`, `tests/ci_watch_c001_idle_driver.rs`, RunControl and session-turn protocol authorization tests, M016/M017; `cargo fmt --all -- --check`; `cargo clippy --workspace --all-targets -- -D warnings`; `scripts/verify.sh quick` and existing authorization/projection/scheduler guards. Fake model and local HTTP only; no new permanent CI lane or paid inference required.

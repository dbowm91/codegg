## 1. Executive objective, exact missing boundary and stop rule

The C001 daemon-owned `CiWatchIdleDriver` can now advance remote CI status independently of a user/model turn. C002 implemented grant/intent CAS state in `src/scheduler/idle_continuation.rs`, but **no production daemon owns or dispatches an `IdleContinuationCoordinator`**; only tests instantiate it. C003's `tests/async_background_c003_idle_lifecycle.rs::full_idle_lifecycle_notify_only_and_granted_resume` waits for the notice and then **calls `coord.maybe_dispatch(...)` in the harness**, with `FakeContinuationExecutor`. That proves a pluggable coordinator and CAS, not an autonomous daemon-initiated real turn.

Likewise a watch's `JobNotificationService::record_terminal_for_watch` creates a durable notice row, but the current `src/agent/job_notification_recovery.rs::inject_recoverable_job_notifications` appends the `SessionEvent::JobTerminalNotification` only when an agent turn invokes recovery; there is no demonstrated instant live `CoreEvent`/projected client update at remote completion. `src/core/event_log.rs::should_persist` has no job-terminal completion event branch and `src/core/notification.rs::NotificationKind` has no background-job completion kind. Prior tests inspect `pending_for_session()`, not a real subscribed TUI/remote client's live event.

**End state:** a submitted background Bash/Test job or CI watch ends after its originating turn; the running daemon durably records exactly one authenticated terminal completion and publishes an owner-scoped live attention update **with no further user/model/tool requests**. Default `notify_only` never calls a provider. If, and only if, a host-authenticated user/task granted the specific wait a bounded `resume_owner` authorization, the daemon schedules exactly one canonical owner turn using the real session admission/turn runtime, without manual `maybe_dispatch` and without forging a user or bypassing authorization.

**Stop immediately** if work cannot locate/obtain an independently verifiable host-trusted grant path and real canonical turn-admission API. In that case close only the notify/attention delivery sub-slice with evidence and leave idle-provider resume explicitly **blocked**; never replace grant verification with a model-supplied `on_complete` flag or a fake `client_id`.

## 3. Hard invariants / non-goals

- The daemon is the **sole** privileged authority. All model inference is admitted by the existing authenticated session/turn controller and `TurnRuntime`; all machine execution remains behind `JobScheduler`/`JobSubmissionService` plus the normal ToolBroker/sandbox/permissions. No direct provider call from CI callback, no second scheduler, no generic workflow engine.
- Terminal producer must be durable and idempotent: one logical terminal receipt per exact owner/job or CI watch; commit **before** live transport. `CoreEvent` streaming is a hint, not the only evidence. Client reconnect/snapshot replay uses the same identity, never a second notification or a cross-session leak.
- `on_complete=notify_only` is default and can **never** spend model tokens. `resume_owner` requested by an agent is not a consent grant. A grant is issued only by authenticated interactive user/task control at daemon authority, scoped to a single notice, explicit model/connection, principal/session/workspace, allowed tools/sandbox/approval ceilings, token/time/tool budgets, cancellation/revocation and expiry. Past C002 grant rows without attestable trusted origin are non-autonomous.
- A live owner loop and an idle-resume turn are mutually exclusive per session; honor existing active-turn, cancellation, steering and permission prompts. A dropped frontend is not license to impersonate its principal. Terminal failures may be actionable, but do not autonomously retry or amend code unless explicitly covered by the grant.
- Claim/persist accepted turn identity and notice binding before provider entry, fence competing daemons, and treat crash-after-provider-entry ambiguity as `needs_attention`, **never blind replay**. At-most-once *logical admission* is the guarantee; exactly-once external inference cannot be promised.
- Preserve `CiWatchIdleDriver`, CAS lease/expiry/recovery, repo/SHA verification, token/SSRF/redirect/ETag/rate guards, bounded SBC usage, Tool Program M017 idempotent session append, AgentRun M009 routing and foreground Bash/Test. Do not mutate historical M001–M004 or C001–C003 closure reports.
- Scope is **daemon wiring + delivery + tests**, not a new messaging platform, webhooks, app notifications to external devices, generic long-term jobs DSL or expanded Windows sandbox guarantee.

## 4. Ordered work packages

### A. Host/runtime contract and fail-first trajectory

Before code change, map existing `CoreRequest::TurnSubmit`, `SessionPromptSubmit`, session controller/active lease, `RequestAuthorityContext` and `AuthorizationDecision`, model selection, `CoreRuntimeDeps`/daemon construction/shutdown, `TurnRuntime::run_turn`, `EventLog`, projection sink and TUI/remote subscription. Write one short architecture diagram freezing the single host-authority path for (i) trusted grant, (ii) persisted terminal notice, (iii) canonical idle turn submission, (iv) frontend live event and replay.

Create **failing** end-to-end tests that instantiate an actual `CoreDaemon`, own a real session/workspace, use its core request dispatch and subscribed event client, and let a watch/build finish after the original turn exits. The test must NEVER invoke `maybe_dispatch`, `JobNotificationService::pending_for_session` as a substitute for client proof, `CiWatchService::observe_once`, `advance_due_watches` or user-turn submission after completion. Use fake provider at existing **turn runtime boundary**, not fake coordinator invocation. Assert test fails on baseline with no automatic resume/live event.

### B. Daemon-owned continuation and event wake

Promote `ContinuationService` and `IdleContinuationCoordinator` to one `CoreDaemon` lifetime via the narrowest `CoreRuntimeDeps`/daemon construction fields. Wire the existing job terminal transition and C001 `CiWatchIdleDriver` terminal transition through a **single post-commit, durable completion/attention fanout**; the notifier records the one terminal event first, then a bounded daemon-owned wake/scan for pending consented continuations and live client delivery. Handle both machine jobs and CI watches; do not introduce one polling Tokio task per job. A never-received in-memory wake must be healed by restart/reconciliation. Preserve resource fairness, shutdown drain and no long-held CPU permits.

Define who invokes `IdleContinuationCoordinator::maybe_dispatch` automatically from the daemon service, passing host-verified owner status/provider availability and terminal identity. This MUST NOT be the model or test harness, and MUST NOT be triggered by `on_complete` alone.

### C. Real host-only grant and canonical executor

Provide the smallest authenticated user/operator workflow for `approve single continuation`, `revoke`, and `status` through existing daemon request authority (or an already-authorized task/work-order control). The grant is not issued by `NewGrant` with arbitrary self-asserted strings from the model, raw frontend metadata or an unauthenticated socket; resolve the principal/session/workspace/model on the server. Grant request and revocation must be audited; no default `admin/admin`, silent approval or upgrade of existing C002 rows. If feature configuration cannot express this safely, make idle resume unavailable until an explicit authenticated control is present.

Implement a **production** `ContinuationExecutor` adapter that submits through the existing `CoreDaemon` session controller/turn admission and injects the bounded host-authored terminal result with a typed cause. Preserve selected provider identity, model permissions, sandbox ceiling, turn budgets, active-turn exclusivity and authenticated owner attribution. Do not create a synthetic user-role utterance or forged client session; use explicit delegated authorization bound to the grant (new narrow internal typed entry only if normal `TurnSubmit` cannot represent this). Reject absent/stale session, revoked control, unauthorized project, invalid connection, or fail to `needs_attention` before inference. Do not launch a second agent runner.

Persist a deterministic turn/intention ID *and* acceptance receipt at the canonical controller. Clarify `TurnAccepted` vs provider-start semantics; existing C002 `set_intent_turn` before `execute_turn` is not proof that a real turn was admitted. Race before/after durable admission, cancellation and duplicate completion must yield one actual accepted owner turn. An ambiguous provider entry is terminal attention, not retry.

### D. Live completion event and replay for every frontend

Publish a typed, bounded, owner-scoped background completion **via the existing `EventLog` + session projection/replay path** as soon as the durable notice commits, without waiting for `AgentLoop::run`. A live connected TUI, desktop and remote frontend must receive the same event (respect individual project/session authorization, privacy and muted/notification policy), render or expose an actionable job/watch handle/status and allow inspect/cancel via existing authorized controls. A frontend may miss a transient event; on reconnect, the replay/snapshot must recover the identical notice ID and status exactly once. If a new `CoreEvent` or projection variant is necessary, make it additive/version-compatible and wire `should_persist`, publication guards and client compatibility explicitly. No full stdout/stderr, credentials, raw CI logs or remote instructions in trusted system messages.

Never append `JobTerminalNotification` twice if turn-start `job_notification_recovery` executes after the idle daemon published it: reuse M001 semantic idempotency/confirm semantics; do not consume/destroy the pending notice before safe model injection. Handle failure-before-event, event-before-ack, client disconnect and restart by reconciliation; a toast is not the durability authority. Existing `NotificationRouter` can add an optional visible event type if necessary, but it must not become a second completion database.

### E. Verification, docs and truthful closure

Add focused daemon-level tests, e.g. `tests/async_background_c004_production_dispatch.rs` and `tests/async_background_c004_live_attention.rs`, using local fake provider, local fake GitHub, SQLite and actual `CoreRequest`/event subscriber. Update `architecture/agent.md`, `architecture/jobs.md`, `architecture/authorization.md`, `architecture/projection.md`, `architecture/scheduler.md` with real consent, routing, lifecycle and operator controls; update narrow tool/help copy claiming automatic resume only when the approved path is active. Record supported vs unsupported platforms. Do not mark C004 closed until all mandatory gates pass. ## 5. Mandatory acceptance matrix (pass/fail, no simulation loopholes)

1. **Prod idle resume:** Create real `CoreDaemon`/session/user-controlled grant, invoke `ci_watch` or background `test` through the actual model-facing tool/runtime, finish originating turn. On fake CI completion / background job finalization and *without* calling `maybe_dispatch`, `CoreRequest::TurnSubmit`, `ci_watch.status`, or injecting a user message from the harness, daemon automatically **admits and starts exactly one** normal session turn using the actual `TurnRuntime` and fake provider. Assert durable `TurnStarted`/turn admission receipt, correct session/principal/workspace/model/budget/permission snapshot and one provider entry. An injected `FakeContinuationExecutor` alone is insufficient.
2. **True notify-only:** Same idle lifecycle with default, absent grant, invalid/unapproved grant, or model-only `resume_owner`: one persisted terminal notice plus one owner-visible pushed event; zero turn admissions/provider requests. Verify permission denial before work begins.
3. **Live+replay:** Two simultaneously connected clients subscribed with independent identity; owning authorized clients receive one event with job/watch ref at terminal time, unaffiliated client gets none. Disconnect/reconnect and daemon restart yield the same durable notification via session snapshot/replay. No agent turn needed to get it. Verify TUI or adapter projection consumes the typed event, not just internal row polling.
4. **Consent/revocation:** Only authenticated host grants/revokes exact waits. Wrong principal, expired grant, disabled provider, archived session, concurrent active turn, mismatched workspace, user cancel, disabled permission, sandbox `Required` unavailable and token/tool budget exhaustion all prevent idle provider start and leave actionable attention.
5. **CAS/crash:** At least 50 racing duplicate completions / two daemon handles, simulated restart immediately before/after receipt append, projection publish, intent claim, real turn admission and provider start. Exactly one logical session notice, one accepted turn, and no duplicate provider entry. Ambiguous state becomes explicit `needs_attention`; late live event replay cannot spend tokens.
6. **Interoperability:** `tests/ci_watch_m004_completion.rs`, `tests/ci_watch_c001_idle_driver.rs`, `tests/job_continuation_c002_idle_resume.rs`, `tests/async_background_c003_idle_lifecycle.rs`, `tests/job_notification_m001_contract.rs`, `tests/job_background_test_slice.rs`, `tests/bash_background_m002_routes.rs`, `tests/job_continuation_m003_visibility.rs`, M016/M017 Tool Program suites, session controller/transport auth/projection, scheduler restart, command-intent and sandbox authority remain green; no foreground semantic change.
7. **Host evidence:** `cargo fmt --all -- --check`; `cargo clippy --workspace --all-targets --locked -- -D warnings` (respect no-`--all-features` repo policy); `scripts/verify.sh quick`; `scripts/check_scheduler_bypass.py`; `scripts/check_execution_ownership.py`, core-boundary/authorization/projection guards. Obtain exact-head hosted `CI / verify` + relevant Desktop E2E on the merge candidate, with actual run/commit/status recorded before saying merge-ready; unsupported native Windows/macOS, live provider and real GitHub qualification are explicitly unverified rather than invented.
8. **Mainline integration:** Reconcile divergence from `main` on a separate integration PR/merge head, rerun the gates and inspect the changed turn/auth/event ownership seams. Do not claim this branch or C004 is merged, released or production-qualified from tests run only on an older implementation SHA.

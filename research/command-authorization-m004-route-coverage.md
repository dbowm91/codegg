## Test-only admission model

`tests/command_routing_adversarial.rs` contains `m004_test_only_route_admitted`. It is a design oracle only and is not called by production code. It requires an Allow receipt, matching snapshot/receipt policy revisions, a profile matching the reported request, and route-specific obtained evidence. A constrained raw route needs observed outside-root denial under Landlock; a specialized FullHost route requires explicit FullHost plus disabled containment; Git filter routes remain refused while C002 is blocked. A status label by itself never counts as observed enforcement.

The oracle is intentionally stricter than a command classifier and models no production guarantee. The real-child fixtures in `tests/sandbox_containment.rs` establish Landlock filesystem behavior independently; they do not prove that the Test/Python/Git route transmits the same policy.

## Evidence and remaining gates

- `active_route_matches_authorization` in `src/tool/bash/process.rs` limits production active Bash routing to a FullHost snapshot when an accepted context is present. A missing context is accepted for legacy/harness callers and cannot be treated as daemon-route authorization.
- `TestJobExecutor` currently enters the domain-owned test-runner child launcher. The route does not receive the accepted sandbox profile.
- `PythonJobExecutor` uses ManagedProcessService, but the Python policy is independently derived from script mode/content and does not carry the accepted execution snapshot into `ManagedProcessRequest`.
- Git typed authority does not make workspace Git metadata, hooks, filters, or network transport contained. Linux C002/C003 remain prerequisites.
- No production route was promoted. No new fallback to FullHost, raw Git, or inherited credentials was added. No accepted Deny is rerouted.
- Outside-root secret denial, helper/status substitution, and no-target setup failure are covered by the existing sandbox helper real-child suite; these are helper/filesystem facts, not cross-route parity results. The route fixture does not claim stale-receipt revocation, agent child lease behavior, or enhanced proc/network/IPC guarantees.
